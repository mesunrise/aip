# v0.1 需求文档

## 版本信息

**版本号：** v0.1  
**版本名称：** 通信验证  
**核心目标：** 验证APP与服务端的通信  
**开发周期：** 2-3天  
**状态：** ✅ 已完成

## 核心目标

建立云端与Android App之间的基础WebSocket通信，验证通信可靠性。

**简单来说：** 确保App能和服务器说上话！

## 功能需求

### 1. WebSocket连接 ✅

**需求描述：**
- App能连接到云端服务器
- 连接成功后显示状态
- 连接失败时显示错误

**验收标准：**
- [ ] App点击"连接"按钮后能成功连接
- [ ] 连接成功显示"✅ 已连接"
- [ ] 连接失败显示错误信息

### 2. 消息发送 ✅

**需求描述：**
- App能向服务器发送消息
- 服务器能接收并记录消息

**验收标准：**
- [ ] App输入消息后点击"发送"
- [ ] 服务器日志显示收到消息
- [ ] App显示发送成功

### 3. 消息接收 ✅

**需求描述：**
- 服务器能向App发送消息
- App能接收并显示消息

**验收标准：**
- [ ] 服务器发送消息
- [ ] App收到并显示在日志区域
- [ ] 消息内容完整正确

### 4. 心跳保活 ✅

**需求描述：**
- App定期发送心跳消息
- 服务器响应心跳
- 保持连接活跃

**验收标准：**
- [ ] 每30秒自动发送心跳
- [ ] 服务器响应心跳确认
- [ ] 连接保持稳定

### 5. 服务器主动推送 ✅

**需求描述：**
- 连接成功后，服务器立即发送"连接成功"消息
- 连接5秒后，服务器主动发送"连接5秒"消息
- 验证服务器主动推送能力

**验收标准：**
- [ ] 连接后立即收到"连接成功"
- [ ] 5秒后收到"连接5秒"
- [ ] App正确显示推送消息

## 非功能需求

### 1. 简单性
- 代码简单易懂
- 不引入复杂逻辑
- 专注通信验证

### 2. 可靠性
- 连接稳定
- 消息不丢失
- 错误有提示

### 3. 可测试性
- 功能可独立测试
- 日志清晰可读
- 问题易于定位

## 技术实现

### Android端

**核心组件：**
1. **WebSocketClient** - WebSocket客户端
   - 连接管理
   - 消息发送
   - 消息接收

2. **MainActivity** - 主界面
   - 连接控制
   - 消息输入
   - 日志显示

**技术栈：**
- Kotlin
- OkHttp WebSocket
- Android SDK

### 服务器端

**核心组件：**
1. **FastAPI** - Web框架
2. **WebSocket路由** - 处理连接
3. **消息处理** - 接收和发送

**技术栈：**
- Python 3.8+
- FastAPI
- Uvicorn

## 通信协议

### 消息格式

所有消息使用JSON格式：

```json
{
  "type": "消息类型",
  "content": "消息内容",
  "timestamp": "时间戳"
}
```

### 消息类型

#### 1. 心跳消息
**App → 服务器：**
```json
{
  "type": "heartbeat",
  "timestamp": "2026-05-15T10:00:00"
}
```

**服务器 → App：**
```json
{
  "type": "heartbeat_ack",
  "timestamp": "2026-05-15T10:00:00"
}
```

#### 2. 普通消息
**App → 服务器：**
```json
{
  "type": "message",
  "content": "测试消息",
  "timestamp": "2026-05-15T10:00:00"
}
```

**服务器 → App：**
```json
{
  "type": "message_ack",
  "content": "服务器收到: 测试消息",
  "received_message": "测试消息",
  "timestamp": "2026-05-15T10:00:00"
}
```

#### 3. 连接成功
**服务器 → App：**
```json
{
  "type": "connected",
  "message": "连接成功",
  "timestamp": "2026-05-15T10:00:00"
}
```

#### 4. 服务器推送
**服务器 → App：**
```json
{
  "type": "server_push",
  "message": "连接5秒",
  "timestamp": "2026-05-15T10:00:05"
}
```

## 验收测试

### 测试用例

#### TC01: 连接测试
1. 启动服务器
2. 打开App
3. 输入服务器地址
4. 点击"连接"按钮
5. **预期：** 显示"✅ 已连接"

#### TC02: 消息发送测试
1. 确保已连接
2. 输入测试消息"Hello"
3. 点击"发送"按钮
4. **预期：** 收到"服务器收到: Hello"

#### TC03: 心跳测试
1. 确保已连接
2. 等待30秒
3. 观察日志
4. **预期：** 看到心跳消息

#### TC04: 服务器推送测试
1. 连接服务器
2. 立即查看日志
3. **预期：** 收到"连接成功"
4. 等待5秒
5. **预期：** 收到"连接5秒"

#### TC05: 断线重连测试
1. 确保已连接
2. 关闭服务器
3. **预期：** App显示断开
4. 重启服务器
5. **预期：** App自动重连
